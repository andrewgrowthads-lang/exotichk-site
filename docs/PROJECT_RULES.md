# Правила проекта

Канонический источник требований. Архитектурные решения фиксируются в `docs/ARCHITECTURE.md` и не должны противоречить этому документу.

## Ключевой принцип

Максимально простой, быстрый, mobile-first SEO-каталог.

## Основная пользовательская воронка

```text
Google / referral website
→ country page / district page
→ profile
→ Telegram / WhatsApp manager
```

## Функционал

- 2 страны
- 2–3 района на страну
- первоначально 10–20 профилей на страну
- профили добавляются через CMS
- English + Traditional Chinese для Hong Kong
- другие языки должны быть расширяемыми
- Telegram
- WhatsApp
- Telegram channel как дополнительная ссылка

Явно вне области проекта:

- никаких платежей
- никаких аккаунтов клиентов
- никаких бронирований
- никаких пользовательских отзывов
- никаких личных кабинетов
- никакого внутреннего чата

## Предпочтительный стек

- Next.js
- TypeScript
- React
- Tailwind CSS
- Sanity CMS
- Vercel
- Cloudflare

## Архитектурные правила

1. Не добавлять отдельный backend без явной необходимости.
2. Не добавлять PostgreSQL, Redis, GraphQL, NestJS и другие инфраструктурные компоненты без прямого запроса владельца проекта.
3. Предпочитать простое решение сложному.
4. Не менять URL architecture без предварительного объяснения.
5. Все публичные SEO-страницы должны быть доступны server-side.
6. Основной контент не должен зависеть от client-side rendering.
7. Не устанавливать зависимость, если задачу разумно решить средствами уже используемого стека.
8. Перед крупным рефакторингом сначала объяснить, зачем он нужен.
9. Не удалять существующий работающий функционал ради новой реализации без необходимости.
10. Все изменения должны учитывать mobile UX, SEO и Core Web Vitals.
11. Не создавать ненужные API endpoints.
12. Не создавать собственную authentication system.
13. Не хранить секреты во frontend.
14. TypeScript strict mode.
15. Код должен оставаться понятным другому senior-разработчику.

## Правило разрешения сомнений

При любых сомнениях выбирается **SIMPLE > CLEVER**.

## Ожидаемый масштаб

50–100 профилей — нормальная рабочая нагрузка. Система не проектируется под миллионы пользователей.
